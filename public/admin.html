# Online Sphere Upgrade Plan ## Phase 1 — Dashboard preservation - Keep `public/dashboard.html`, `public/dashboard.css`, and `public/dashboard.js` visually unchanged. - Ensure the approved dark navy, gold, teal, and bottom navigation remain exactly as approved. ## Phase 2 — Secure backend foundation - Harden API endpoints with rate limiting and security headers. - Protect admin APIs through role verification and owner-only access. - Add logs for sensitive actions and member login history. ## Phase 3 — Member platform modules - Add wallet, package activation, opportunities, task submissions, and learning endpoints. - Keep all important financial state and balances sourced from server-side records only. ## Phase 4 — Payments and referrals - Verify M-Pesa Daraja callbacks before wallet or membership activation updates. - Track referral registrations and incentivize only verified membership activations. - Maintain the commission policy at 10% of qualifying verified membership activation fees, subject to policy and internal approval. ## Phase 5 — Owner admin control centre - Restrict all admin functionality to the authorized owner account. - Log sensitive actions and expose a dedicated admin dashboard. - Do not allow ordinary members to reach administrator routes or pages. ## Phase 6 — Deployment preparation - Keep secrets in the environment and never in frontend code. - Prepare production variables for the backend and payment callbacks. - Use secure hosting and backend configuration for deployment. ## Phase 7 — Final verification - Validate registration, login, dashboard loading, payment verification, and admin access restrictions. - Ensure no dashboard redesign or visual policy deviations occur. This project is intentionally staged to preserve the working dashboard while expanding the secure platform functionality around it.
